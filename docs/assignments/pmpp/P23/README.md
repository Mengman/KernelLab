# P23：一个算子的完整实验复盘

## 你要学会什么

从 P05、P10 或 P16 选择一个完成算子，写出别人能够复现的完整实验。重点是把问题、假设、改动、证据和局限连接起来，而不是列所有优化术语。

## 开始前

前置：P06，以及选择题的已完成实现。阅读 PMPP 中关于回顾 P05/P10/P16 和性能报告方法的主题，按所用版本目录定位，不假定章节号一致。遵循 [统一实验与教学规则](../RULES.md)。

4090D 使用 cuda-sm89，GB10 未运行写“未测”。本机没有 CUDA 时先做接口、CPU reference、手算测试和报告草稿；GPU 部分在服务器验证。工具不可用如实标记，性能结论可用计算量/访存分析辅助，不伪造 profiler 数据。

### 输入输出与边界

只选择一个主要任务，保留基线和优化版。2–4 页指打印或导出后的大致篇幅，优先内容完整，不用调整字体凑页数。报告不得将未测硬件或推测当实测。

### 创建或修改的文件

- reports/p23.md：报告正文。
- reports/results/p23/：保存原始实验输出。
- 复用所选作业的已完成程序；必要时为其增加实验输出，不另建空库或空程序。

## 按步骤完成

1. 在 reports/p23.md 用一段话提出具体问题，例如 tile 填充是否减少转置冲突，写出先验预测。
2. 列基线与最终实现差异、数学合同、边界、输入、数据类型、容限和源码校验值或版本。
3. 选择至少三个规模及一个非整齐尺寸，重新运行正确性与同口径性能对照，保存 reports/results/p23/ 日志。
4. 写性能表、加速比、资源/算法分析和瓶颈证据；工具不可用明确标出，至少保留一个失败或无收益尝试。
5. 写结论适用范围和下一步的一个可验证假设，最后由另一台可用环境或指导者按报告命令复跑。GB10 无法运行继续未测。

先完成第一步交由指导者检查，再推进后续；本题不提供完整实现。保留基线，每次优化只改变一个变量。

### 运行与保存输出

本题复用前置作业的实际目标与命令。先运行对应正确性程序，再运行实验；报告逐项列出可执行命令，不写尚未实现的参数。

### 计时与指标

默认预热 20 次、正式测量 100 次，记录最小和中位耗时，统计方式沿用 nearest-rank。GPU 用 CUDA Event；主机工作或完整流水线需要另列 CPU 单调时钟结果。执行前恢复的状态、哪些阶段计时及哪些阶段排除，必须写入报告。

沿用所选算子的 FLOP/字节口径，记录最小和中位 ms；不为了总结创造新的不明指标。

## CUDA 工具练习

按 [工具练习路线](../TOOLING.md) 学习命令、编译方式和指标解释。先正确性，再整体时间线，最后按问题采集单 kernel；普通 benchmark 与工具运行分开。

1. 最终报告必须包含一次 nsys 整体定位和一次 ncu/资源分析的代表 kernel 证据（工具不可用则给采集方案与错误证据）。
2. 提交基线与改动报告路径、相同输入、工具版本、可复现命令、解释和普通测速结果；至少否定或修正一个原先预测。

交付：在本题报告列工具版本、实际命令、配置、报告/日志路径、观察事实和下一步假设。工具可用时完成本节是练习验收的一部分；不可用则保存错误和采集方案，指标写未测，不阻塞其他可完成阶段。新工具练习不追溯否定 P01 已完成状态，P21/PA 仍为选做。


## 完成标准

- 2–4 页报告覆盖基线、改动、正确性、环境、性能、瓶颈、失败与下一步。
- 有原始日志、可复现命令和源码版本；跨环境变化如实记录。
- 预测与结论可由证据检验，至少一个结论有范围限制。
- 有独立正确性测试、完整环境与命令、原始日志；报告区分实测、规格和推测。未运行的设备或工具明确注明。

## 常见问题

- 写成过程流水账，没有问题和结论。
- 只留下最快配置而丢失基线。
- 把缓存推测写成已经工具确认。

# P06：第一张可复现性能对照表

## 你要学会什么

把前四题变成一组口径一致的实验，练习先预测再用证据解释。此题整理已有程序，不要求发明新的 kernel。

## 开始前

前置：P02–P05。阅读 PMPP 中关于回顾 P02–P05 的计时、计算量和资源分析的主题，按所用版本目录定位，不假定章节号一致。遵循 [统一实验与教学规则](../RULES.md)。

4090D 使用 cuda-sm89，GB10 未运行写“未测”。本机没有 CUDA 时先做接口、CPU reference、手算测试和报告草稿；GPU 部分在服务器验证。工具不可用如实标记，性能结论可用计算量/访存分析辅助，不伪造 profiler 数据。

### 输入输出与边界

保留每个任务的数据类型、尺寸含义与 launch 参数，不把不同算法或输入的时间直接排成优劣榜。只在同一操作的基线和优化版之间计算加速比。

### 创建或修改的文件

- reports/p06.md：报告正文。
- reports/results/p06/：保存原始实验输出。
- benchmarks/p06/run.sh：运行已有目标的脚本，先检查目标与命令确实存在。
- 复用所选作业的已完成程序；必要时为其增加实验输出，不另建空库或空程序。

## 按步骤完成

1. 在 reports/p06.md 列出 P02–P05 版本、任务和原始结果来源，指出缺失的环境或口径。
2. 选择向量每数组 16 MiB、滤波 1024×1024、GEMM 512×512×512、转置 1024×1024；P04 分支任务使用 n=2^20 的四类分布。保持同一服务器和 Release 配置。
3. 创建 benchmarks/p06/run.sh，逐个调用已实现程序并保存到 reports/results/p06/；现有程序若无参数，可按已记录的固定规模运行，不编造不存在的 CLI。
4. 统一为预热 20 次、测量 100 次，列出最小值、中位数、输入、算法 GB/s 或 GFLOP/s、GPU 和编译配置；不适用的列写不适用。
5. 每个优化先写预测，再填实测与加速比；解释至少一项成功和一项无收益的尝试，若此前没有失败尝试，追加一个单变量实验。

先完成第一步交由指导者检查，再推进后续；本题不提供完整实现。保留基线，每次优化只改变一个变量。

### 运行与保存输出

本题复用前置作业的实际目标与命令。先运行对应正确性程序，再运行实验；报告逐项列出可执行命令，不写尚未实现的参数。
实现脚本后在项目根目录运行 `bash benchmarks/p06/run.sh`，脚本需按步骤保存原始输出。

### 计时与指标

默认预热 20 次、正式测量 100 次，记录最小和中位耗时，统计方式沿用 nearest-rank。GPU 用 CUDA Event；主机工作或完整流水线需要另列 CPU 单调时钟结果。执行前恢复的状态、哪些阶段计时及哪些阶段排除，必须写入报告。

加速比=同输入基线中位时间/优化中位时间。表格中的带宽与 FLOP 公式引用对应作业，不将元素/s、GB/s、GFLOP/s 混为同一量。

## CUDA 工具练习

按 [工具练习路线](../TOOLING.md) 学习命令、编译方式和指标解释。先正确性，再整体时间线，最后按问题采集单 kernel；普通 benchmark 与工具运行分开。

1. 新增 reports/p06.md 工具对照页：选择一个整段 nsys 报告与一个代表 kernel 的 ncu 报告，写出命令、shape、launch、版本及 replay 设置。
2. 形成一次假设→采集→改动→正确性→普通 benchmark 复测的证据链，并解释 profiler 耗时与原 20/100 中位数为什么可能不同。

交付：在本题报告列工具版本、实际命令、配置、报告/日志路径、观察事实和下一步假设。工具可用时完成本节是练习验收的一部分；不可用则保存错误和采集方案，指标写未测，不阻塞其他可完成阶段。新工具练习不追溯否定 P01 已完成状态，P21/PA 仍为选做。


## 完成标准

- 同操作不同版本共用输入与测量口径。
- 脚本执行失败能返回非零状态，日志与报告一一对应。
- 至少四类任务有数据、预测、实际解释；GB10 未测明确标注。
- 有独立正确性测试、完整环境与命令、原始日志；报告区分实测、规格和推测。未运行的设备或工具明确注明。

## 常见问题

- 把旧环境的表格直接拼接：记录变化或重新测量。
- 仅列更快的结果：保留失败与无收益配置。
- 脚本 tee 掩盖程序失败：使用 pipefail。
